# Football Intelligence AI implementation contract

Single-process FastAPI + sqlite3 WAL, React TypeScript/Vite compiled to web/dist and served by FastAPI. Python entry backend.main:app on port 8000, optional PORT. No paid services. Actual CC0 openfootball results/fixtures plus optional football-data.org v4 account. No fabricated records or metrics. UTC storage, Asia/Hong_Kong display. sqlite file data/football.db (ignored); API keys environment only. No key returned or logged. Config local environment .env ignored, not required.

## Normalized match dictionary
id: deterministic string; league: PL/PD/BL1/SA/FL1; season: 2023-24; home, away: canonical strings; kickoff: ISO UTC timestamp; kickoff_precision: date/exact; status: FINISHED/SCHEDULED/POSTPONED; home_goals, away_goals nullable ints; source: openfootball/football-data.org; source_url; fetched_at ISO UTC; result_available_at: ISO UTC nullable. Openfootball date-only fixtures use midnight UTC only as sortable sentinel; UI must say time unknown, never present sentinel as confirmed kickoff. Conservative historical result availability: following day + 12h UTC (36h after date midnight); exact API availability no earlier than kickoff+3h, and current fetched_at for prospectively ingested results. Historic research is retrospective and can't prove as-published data availability; show limitation explicitly. Only results with result_available_at strictly before prediction cutoff are allowed. Team names must be canonicalized identically across providers.

## Module responsibilities/interfaces
backend/providers.py: LEAGUES dict; async sync_openfootball(seasons: list[str], leagues:list[str]) -> {matches:list[dict],errors:list[str],...}; async sync_football_data(api_key:str,leagues:list[str]) same shape. Documentation DATA_SOURCES.md. Validate schemas, retries/backoff, bounded concurrency, 429 handling, no secrets in exceptions. Reject results dated in the future. Provider fixtures never generated.
backend/models.py: ModelEngine(history:list[dict], as_of:str).predict(home:str,away:str,league:str) -> dict with matrix:list[list[float]], expected_goals:{home,away}, probabilities:{home,draw,away}, models:{...}; other public methods agreed with backend agent. Goal matrix is sole source for all markets. fit DC Poisson with recency/ridge, dynamic Elo, sklearn gradient boosting trained on prior-only features. backend/backtest.py run_backtest(matches:list[dict],league:str) -> JSON serializable report with actual sample counts/periods/models, independent chronological train/calibration/validation/test, validation-selected ensemble weights and test-only evaluation. All prediction rows available in report for persistence. Save artifacts via optional path. Communicate exact final interfaces to backend agent and root early.
backend/database.py + backend/service.py + backend/main.py: schema, immutable snapshots, provider ingestion, jobs, inference, API, scheduler. Agent owns API contract below; may extend fields. root handles dependency install, integration, execution, docs/tests as needed.
web/*: UI agent owns. No invented fixture/stat fallbacks; useful empty/error states. Team crests only supplied real URL, otherwise explicitly an initial avatar, not fake logos.

## API contract (JSON)
GET /api/status -> {mode: real/empty, counts:{matches,finished,upcoming,predictions}, sources:[{name,last_sync,status,...}], jobs:[], scheduler:{...}, capabilities:{...}}
GET /api/matches?league=&date=&q=&sort=&window=7 -> {matches:[{...normalized match,prediction: nullable dict}],total,...}; optional window=all for historical browsing. Date filters YYYY-MM-DD HK interpretation.
GET /api/matches/{id} -> {match:normalized match,prediction: nullable dict,versions:[],comparison:{home:{...},away:{...}},report:list[{title,text}],data_gaps:list[str]}
Prediction fields: id,created_at,as_of,model_version,expected_goals:{home,away},probabilities:{home,draw,away},markets:{over_under:[{line,over,under}],btts:{yes,no},scores:[{home,away,probability}],total_goals:[{goals,probability}],asian_handicap:[{line,full_win,half_win,push,half_loss,full_loss}]},confidence:{label,score,reasons},data_quality:{score,available,missing}, matrix, source, historical:boolean.
GET /api/teams?league=&q= -> {teams:[{name,league,matches,elo,...}]}
GET /api/teams/{name}?league= -> {team:...,form5:[],form10:[],...}
GET /api/history?league=&limit=100 -> {predictions:[{...prediction,match:{...},actual:nullable,outcome:nullable}],total,...}; retrospective historical backtests distinguish from genuine pre-match saved predictions.
GET /api/performance?league= -> {reports:[{league,train_period,validation_period,test_period,sample_count,models:[{name,log_loss,brier,ece,accuracy,n,calibration_bins:[]}],...}],monitoring:{...}}
GET /api/settings -> {provider:...,api_key_configured:boolean,admin_configured:boolean,sources:[],limitations:[]}
POST /api/admin/sync body {provider:openfootball/football-data.org} -> {job_id,status}; POST /api/admin/train body {league:PL or all} -> {job_id,status}; POST /api/admin/predict -> same. Background tasks persisted status, no blocking UI. Admin writes require X-Admin-Token when ADMIN_TOKEN set; no configured ADMIN_TOKEN: only local access permitted; backend should enforce host/origin safeguards. Frontend admin token entered client in memory, never localStorage. API key not entered via public UI: account steps + environment secret instructions only.
GET /api/jobs/{id} -> job. GET /health -> real db readiness.
Scheduler hourly provider sync, daily prediction refresh, weekly retraining if enough data; do not claim lineup retraining if unsupported. Track failed tasks/retry times. Never update/delete prediction snapshots; settled result stored separately. Don't create prediction for already started match, except explicit historical backtest path clearly marked retrospective.

Probabilities displayed via largest remainder rounding 1X2 to 100.0. Confidence quality + calibration + model disagreement, not max probability. xG unavailable clearly separate expected_goals. Nothing is betting recommendation.
